# ZMODEM双向传输修复规格

## 目标

在 smithwhere fork 的 Windows x64 桌面客户端中，修复 SSH 会话下 `lrzsz` 的 ZMODEM 下载和上传。保留 v0.30.29 版本号，发布标题为 `OpenFinalShell v0.30.29`，只构建 Windows x64 安装版与便携版。

## 当前根因

v0.30.29 的 `ShellSession` 把 SSH channel 的原始数据直接排入终端输出队列；依赖中没有 `zmodem.js`，因此客户端不解析 ZMODEM 握手。`sz` 协议头会被显示成 `**B000...`，`rz` 也不会启动本地上传选择流程。

## 设计与行为

- 在主进程 SSH channel 字节流处使用一个按 shell 隔离的 ZMODEM Sentry，先解析原始 Buffer，再将普通终端字节送入原有队列和字符集解码器。
- `sz <path>`：隐藏 ZMODEM 启动协议字节，弹出原生保存窗口；以流方式保存字节不变的文件。文件名仅作为安全清理后的建议名，用户选择的路径决定实际目标。每次传输完成或取消后允许同一会话再次传输。
- `rz`：用户输入的字母 `rz` 必须在 SSH 会话终端中可见，且命令仍发送到远端；远端发起 ZMODEM 接收后打开多选文件窗口，逐个流式发送所选文件。
- `rz waiting to receive.` 与随后出现的 shell 提示符必须分行。不得隐藏裸 `rz` 的本地输入或远端回显。
- 处理跨 SSH chunk 的协议帧、协议解析错误、重复传输、文件选择取消、磁盘错误、channel 关闭和流背压。错误不得使 SSH shell 或主进程崩溃；不完整下载不得留在最终目标路径。
- ZMODEM 控制响应以原始字节写回 SSH channel，不经过字符集转换。普通终端内容继续使用原有编码和渲染路径。

## 发布约束

- `package.json` 版本保持 `0.30.29`；tag 为 `v0.30.29`；Release 标题为 `OpenFinalShell v0.30.29`。
- 发布仓库为 `smithwhere/openfinalshell`；客户端 updater feed 与手动更新入口指向 fork。
- 此 tag 仅运行 Windows x64 构建，资产含 x64 安装版、便携版及 electron-updater 所需元数据。macOS、Linux、Windows ia32/ARM64 和 Android 构建在此 tag 上跳过。

## 验收条件

1. `sz /root/.ssh/id_ed25519` 打开保存窗口，终端不显示 `**B000...`，保存文件与远端内容 SHA-256 一致。
2. 同一 SSH shell 连续执行两次 `sz`，两次都能打开保存窗口并成功接收。
3. 输入 `rz` 时界面显示 `rz`，本地多选窗口弹出，所选文件能 byte-for-byte 上传。
4. `rz waiting to receive.` 后的 shell 提示符从新行开始。
5. 取消对话框、切分协议帧和关闭会话时状态能恢复，shell 仍可继续输入普通命令；没有不完整目标文件。
6. v0.30.29 fork Release 只包含 x64 Windows 客户端构建及其更新元数据。
